# คู่มือผู้ดูแลระบบ (Administrator User Guide)

ระบบบริการลูกค้าและจัดการ Ticket — บริษัท บางกอกยูนิเทรด จำกัด

---

## 1. ภาพรวม

| ส่วน | URL | ผู้ใช้ |
|------|-----|--------|
| พอร์ทัลลูกค้า | `https://<โดเมน>/` และ `/request/<ประเภท>` | ลูกค้า (เปิดจาก LINE Rich Menu ได้) |
| ติดตามสถานะ | `https://<โดเมน>/track` | ลูกค้า (ใช้ลิงก์ติดตามสถานะที่ได้รับ) |
| ระบบหลังบ้าน | `https://<โดเมน>/admin` | เจ้าหน้าที่ BUC |

### บทบาทผู้ใช้

| บทบาท | สิทธิ์หลัก |
|-------|-----------|
| **System Administrator (ADMIN)** | ทุกอย่าง รวมถึงเมนูผู้ดูแลระบบ |
| **Department Manager (MANAGER)** | Ticket ของแผนกที่สังกัด, มอบหมายงาน, โอนงาน, เปลี่ยนสถานะ, มอบหมายแบบกลุ่ม, ส่งออก CSV, ดูรายงาน |
| **Staff (STAFF)** | Ticket ที่ได้รับมอบหมาย และ (ค่าเริ่มต้น) คิวงานของแผนกตนเอง, รับงาน (Take), เปลี่ยนสถานะงานของตน, บันทึกความคิดเห็น, โอนงาน |
| **ลูกค้า** | ไม่ต้องมีบัญชี — ส่งคำขอและดูสถานะ Ticket ของตนผ่านลิงก์ติดตามสถานะที่เป็นความลับ |

## 2. เริ่มต้นใช้งานครั้งแรก (Checklist)

1. เข้าสู่ระบบด้วยบัญชีผู้ดูแลที่สร้างตอนติดตั้ง (`/admin/login`) และเปลี่ยนรหัสผ่าน
2. **แผนก** — ตรวจสอบ 5 แผนกเริ่มต้น (ฝ่ายขาย, ฝ่ายโลจิสติกส์, ฝ่ายบริการ, ฝ่ายบัญชี, ฝ่ายบริการลูกค้า) และใส่อีเมลกลางของแผนก (ถ้ามี)
3. **ผู้ใช้งาน** — สร้างบัญชีเจ้าหน้าที่และหัวหน้าแผนก กำหนดบทบาทและแผนก
4. **ประเภทคำขอ** — ตรวจสอบแผนกรับผิดชอบเริ่มต้นของแต่ละประเภท (ค่าเริ่มต้นตามตาราง)
5. **การตั้งค่า** — ตรวจสอบ/แก้ไข
   - ประกาศความเป็นส่วนตัว (`privacy.notice_th/en`) — **ข้อความเริ่มต้นเป็นแม่แบบ ต้องให้ฝ่ายกฎหมาย/DPO ตรวจสอบ** และเพิ่มเวอร์ชัน (`privacy.notice_version`) ทุกครั้งที่แก้ไข
   - เป้าหมายการให้บริการ (`service_targets`) — **ค่าเริ่มต้นเป็นตัวอย่าง ไม่ใช่ SLA ตามสัญญา**
   - ระยะเวลาเก็บข้อมูล (`privacy.retention_days`)
   - เบอร์โทร/อีเมลติดต่อที่แสดงบนพอร์ทัล
6. **LINE Rich Menu** — คัดลอก URL 6 รายการจากเมนู *Integrations* ไปตั้งค่าใน LINE Official Account Manager (ดู [LINE_INTEGRATION.md](LINE_INTEGRATION.md))
7. ทดลองส่งคำขอจากมือถือจริง (ทั้ง iOS และ Android ผ่าน LINE) แล้วตรวจสอบว่า Ticket เข้าแผนกถูกต้อง

| ประเภทคำขอ | รหัส | เลข Ticket | แผนกเริ่มต้น |
|-----------|------|-----------|-------------|
| สอบถามผลิตภัณฑ์ | PRODUCT | BUC-PRD-ปปปป-nnnnn | ฝ่ายขาย |
| ติดตามการจัดส่ง | DELIVERY | BUC-DLV-… | ฝ่ายโลจิสติกส์ |
| แจ้งซ่อม / บริการ | SERVICE | BUC-SRV-… | ฝ่ายบริการ |
| ขอใบเสนอราคา | QUOTATION | BUC-QUO-… | ฝ่ายขาย |
| ติดต่อฝ่ายบัญชี | ACCOUNTING | BUC-ACC-… | ฝ่ายบัญชี |
| ติดต่อเจ้าหน้าที่ | GENERAL | BUC-GEN-… | ฝ่ายบริการลูกค้า |

เลขลำดับแยกตามประเภทและเริ่มใหม่ทุกปี (ปี ค.ศ. ตามเวลาประเทศไทย) และจะไม่ถูกนำกลับมาใช้ซ้ำแม้ Ticket ถูกยกเลิก

## 3. การจัดการ Ticket (สำหรับทุกบทบาท)

### 3.1 รายการ Ticket
- ค้นหาด้วยเลข Ticket, เรื่อง, ชื่อลูกค้า, ผู้ติดต่อ, เบอร์โทร หรือค่าในแบบฟอร์ม (เช่น Serial Number)
- กรองตามสถานะ, ประเภท, แผนก, ผู้รับผิดชอบ, ความสำคัญ, ช่วงวันที่, งานเกินกำหนด
- คลิกหัวคอลัมน์เพื่อเรียงลำดับ
- ป้าย **ตัวอย่าง (Sample)** = ข้อมูลทดสอบ ไม่ใช่ข้อมูลลูกค้าจริง
- Manager/Admin: เลือกหลายรายการเพื่อ **มอบหมายแบบกลุ่ม** และ **ส่งออก CSV** (เปิดใน Excel ได้ภาษาไทยถูกต้อง)

### 3.2 หน้ารายละเอียด Ticket
- **ข้อมูล Ticket / ลูกค้า / การมอบหมาย / ไทม์ไลน์ / ความคิดเห็น / ไฟล์แนบ / การดำเนินการ**
- รูปภาพที่ลูกค้าแนบแสดงเป็นแกลเลอรี คลิกเพื่อดูเต็มจอ (ใช้ลูกศรซ้าย/ขวา, Esc เพื่อปิด) และดาวน์โหลดได้ (การดาวน์โหลดถูกบันทึกใน Audit Log)

### 3.3 การดำเนินการ
| การดำเนินการ | วิธีใช้ |
|-------------|--------|
| **รับงาน** | Staff กด "รับงานนี้" สำหรับ Ticket ที่ยังไม่มีผู้รับผิดชอบในแผนกตน |
| **มอบหมาย** | Manager เลือกผู้รับผิดชอบ (ต้องอยู่ในแผนก), ความสำคัญ, วันครบกำหนด — Ticket ที่เป็น "รับเรื่องใหม่" จะเปลี่ยนเป็น "มอบหมายงานแล้ว" อัตโนมัติ |
| **โอนแผนก** | เลือกแผนกใหม่และระบุเหตุผล — ประวัติการโอนถูกเก็บไว้ทั้งหมด ผู้รับผิดชอบเดิมจะถูกล้าง |
| **เปลี่ยนสถานะ** | เลือกสถานะที่อนุญาต (ตาม Workflow) ใส่ *หมายเหตุภายใน* และ/หรือ *ข้อความถึงลูกค้า* |
| **ขอข้อมูลเพิ่มเติมจากลูกค้า** | เปลี่ยนเป็น "รอข้อมูลลูกค้า" พร้อมข้อความถึงลูกค้า (บังคับ) — เมื่อลูกค้าตอบกลับผ่านหน้าติดตามสถานะ Ticket จะกลับเป็น "กำลังดำเนินการ" อัตโนมัติ |
| **ดำเนินการเสร็จสิ้น / ปิดงาน** | เปลี่ยนเป็น "ดำเนินการเสร็จสิ้น" แล้ว "ปิดงาน" (การปิด/ยกเลิกโดยตรงจากงานที่ยังเปิดอยู่ทำได้เฉพาะ Manager/Admin และต้องระบุเหตุผล) |
| **ความคิดเห็น** | *บันทึกภายใน* — ลูกค้าไม่เห็น / *อัปเดตถึงลูกค้า* — แสดงในหน้าติดตามสถานะและส่งอีเมลถึงลูกค้า (ถ้ามีอีเมล) |
| **ออกลิงก์ติดตามใหม่** | เมื่อลูกค้าทำลิงก์หาย — ลิงก์เดิมจะใช้ไม่ได้ทันที คัดลอกลิงก์ใหม่ส่งให้ลูกค้าทางช่องทางที่ยืนยันตัวตนแล้ว |

> ⚠️ ห้ามพิมพ์ข้อมูลภายใน/ความลับในช่อง "ข้อความถึงลูกค้า" — ข้อความนี้ลูกค้าเห็นทั้งหมด

### 3.4 สถานะ Ticket

| รหัส | ชื่อ | หมายเหตุ |
|------|-----|---------|
| NEW | รับเรื่องใหม่ | ทุก Ticket เริ่มที่สถานะนี้ |
| REVIEW | กำลังตรวจสอบ | |
| ASSIGNED | มอบหมายงานแล้ว | |
| IN_PROGRESS | กำลังดำเนินการ | |
| WAITING_CUSTOMER | รอข้อมูลลูกค้า | ต้องมีข้อความถึงลูกค้า |
| WAITING_INTERNAL | รอหน่วยงานภายใน | |
| RESOLVED | ดำเนินการเสร็จสิ้น | เปิดงานใหม่ได้ (ต้องระบุเหตุผล) |
| CLOSED | ปิดงาน | เปิดใหม่ได้เฉพาะ Manager/Admin |
| CANCELLED | ยกเลิก | กู้คืนได้เฉพาะ Admin |

ไม่จำเป็นต้องผ่านทุกสถานะ เช่น NEW → RESOLVED ได้ทันที (ปรับได้ที่เมนู Workflow)

### 3.5 การแจ้งเตือน
- ไอคอนกระดิ่งแสดงการแจ้งเตือนในระบบ: Ticket ใหม่เข้าแผนก, ได้รับมอบหมาย, โอนงานเข้าแผนก, ลูกค้าตอบกลับ, งานเกินกำหนด
- อีเมลแจ้งเตือนส่งโดย Worker เบื้องหลัง หากส่งไม่สำเร็จจะลองใหม่อัตโนมัติ (สูงสุด 5 ครั้ง)

## 4. แดชบอร์ดและรายงาน

- **แดชบอร์ด**: การ์ด KPI (ทั้งหมด/ใหม่/เปิดอยู่/กำลังดำเนินการ/รอ/เสร็จสิ้น/ปิด/เกินกำหนด) และกราฟ — คลิกการ์ดเพื่อดูรายการ Ticket ที่เกี่ยวข้อง
- **รายงาน** (Manager/Admin): สรุป Ticket, ภาระงานเจ้าหน้าที่, ประสิทธิภาพ (เวลาตอบกลับครั้งแรก, เวลาแก้ไข, อายุงานค้าง, งานเกินกำหนด) ดาวน์โหลด CSV ได้
- นิยามการคำนวณทั้งหมดอยู่ใน [REPORTS.md](REPORTS.md)
- ตัวเลขทั้งหมดคำนวณจากฐานข้อมูลจริง ข้อมูลตัวอย่างแสดงป้าย Sample และกรองออกได้

## 5. เมนูผู้ดูแลระบบ (ADMIN)

### 5.1 ผู้ใช้งาน
- **สร้างผู้ใช้**: ระบบสร้างรหัสผ่านชั่วคราวและแสดง **ครั้งเดียว** — ส่งให้ผู้ใช้ทางช่องทางที่ปลอดภัย ผู้ใช้ต้องเปลี่ยนรหัสผ่านเมื่อเข้าสู่ระบบครั้งแรก
- **แก้ไข**: ชื่อ, อีเมล, บทบาท, แผนก (ผู้ใช้หนึ่งคนอยู่ได้หลายแผนก)
- **ปิดใช้งาน**: ผู้ใช้ถูกออกจากระบบทันที (ไม่ลบประวัติการทำงาน)
- **รีเซ็ตรหัสผ่าน**: สร้างรหัสชั่วคราวใหม่ ปลดล็อกบัญชีที่ถูกล็อกจากการใส่รหัสผิด

### 5.2 แผนก
เพิ่ม/แก้ไขชื่อ, อีเมลกลาง, ลำดับการแสดงผล — ปิดใช้งานแผนกที่เป็นแผนกเริ่มต้นของประเภทคำขอไม่ได้ (ต้องเปลี่ยนแผนกเริ่มต้นก่อน)

### 5.3 ประเภทคำขอและแบบฟอร์ม
- แก้ไขชื่อ, คำอธิบาย, แผนกเริ่มต้น, ความสำคัญเริ่มต้น, เปิด/ปิดการใช้งาน
- ดู URL สำหรับ LINE Rich Menu
- **แบบฟอร์มเป็นแบบมีเวอร์ชัน**: การแก้ไขฟิลด์ = เผยแพร่เวอร์ชันใหม่ (JSON) Ticket เดิมยังอ้างอิงเวอร์ชันที่ลูกค้าใช้ส่ง ระบบตรวจสอบโครงสร้างก่อนบันทึก (ต้องมีฟิลด์ชื่อหน่วยงาน, ชื่อผู้ติดต่อ, เบอร์โทร และรายละเอียดหลัก)

### 5.4 Workflow
- เปลี่ยนชื่อ/สีของสถานะ
- กำหนดว่าเปลี่ยนจากสถานะใดไปสถานะใดได้ บทบาทใดทำได้ และต้องระบุเหตุผลหรือไม่

### 5.5 กฎการมอบหมายอัตโนมัติ
- เงื่อนไข: ประเภทคำขอ, หมวด (เช่น ประเภทอุปกรณ์), ประเภทลูกค้า, ความสำคัญ → แผนก และ/หรือ ผู้รับผิดชอบ
- กฎทำงานตามลำดับ (ลำดับน้อยก่อน) กฎแรกที่ตรงเงื่อนไขถูกใช้
- **ต้องเปิด `assignment.auto_enabled` ในการตั้งค่า** จึงจะทำงาน (ค่าเริ่มต้น: ปิด)

### 5.6 การตั้งค่า
ดูหัวข้อ 2 ข้อ 5 และคำอธิบายของแต่ละค่าในหน้าจอ

### 5.7 ลูกค้า
ค้นหา แก้ไขข้อมูลหลักลูกค้า (รหัส, ประเภท, เลขผู้เสียภาษี, ที่อยู่) ดูผู้ติดต่อ และบันทึกการจับคู่กับ ERPNext Customer (ยังไม่มีการซิงค์อัตโนมัติ)

### 5.8 Audit Log / Notification Log / Integrations
- **Audit Log**: ใครทำอะไร เมื่อไร จาก IP ใด (เข้าสู่ระบบ, ส่งออกข้อมูล, ดาวน์โหลดไฟล์, การแก้ไขของผู้ดูแล)
- **Notification Log**: สถานะการส่งอีเมล (PENDING/SENT/FAILED/SKIPPED) — กด "ส่งใหม่" สำหรับรายการที่ล้มเหลว; SKIPPED = ยังไม่ได้ตั้งค่า SMTP
- **Integrations**: URL สำหรับ LINE Rich Menu, สถานะ SMTP/LINE/ERPNext, การจับคู่และ Log การเชื่อมต่อ

## 6. PDPA และความปลอดภัย

- ลูกค้าต้องยอมรับประกาศความเป็นส่วนตัวก่อนส่งคำขอ ระบบบันทึกเวอร์ชันและเวลา
- ตั้ง `privacy.retention_days` ตามนโยบายบริษัท: ระบบจะลบข้อมูลส่วนบุคคลของผู้ติดต่อและไฟล์แนบของ Ticket ที่ปิด/ยกเลิกเกินกำหนดโดยอัตโนมัติ
- ห้ามแชร์บัญชีผู้ใช้; ปิดใช้งานบัญชีพนักงานที่ลาออกทันที
- ไม่ส่งลิงก์ติดตามสถานะให้บุคคลอื่นนอกจากลูกค้าเจ้าของเรื่อง

## 7. การแก้ปัญหาเบื้องต้น

| อาการ | สาเหตุ/วิธีแก้ |
|------|---------------|
| เข้าสู่ระบบไม่ได้ "บัญชีถูกล็อกชั่วคราว" | ใส่รหัสผิด 5 ครั้ง รอ 15 นาที หรือให้ Admin รีเซ็ตรหัสผ่าน |
| ไม่เห็น Ticket ที่คาดว่าควรเห็น | ตรวจสอบแผนกของผู้ใช้ และค่า `access.staff_see_department_queue` |
| ลูกค้าไม่ได้รับอีเมล | ดู Notification Log — SKIPPED = ยังไม่ตั้งค่า SMTP, FAILED = ดูข้อความ error |
| ลูกค้าเปิดลิงก์ติดตามแล้วไม่พบข้อมูล | ลิงก์อาจถูกตัด (ต้องมีส่วน `#t=...`) หรือถูกออกลิงก์ใหม่แล้ว — ออกลิงก์ใหม่ให้ลูกค้า |
| ลูกค้าแนบรูปไม่ได้ | รองรับ JPG/PNG ไม่เกิน 10 MB/ภาพ สูงสุด 10 ภาพ (แจ้งซ่อม) — ให้ลูกค้าลองเลือกจากคลังภาพแทนกล้อง หรือเปิดลิงก์ในเบราว์เซอร์ภายนอก |
| แบบฟอร์มแจ้ง "มีการปรับปรุง" | มีการเผยแพร่แบบฟอร์มเวอร์ชันใหม่ ให้ลูกค้าโหลดหน้าใหม่ |
